# 화면 및 대화 흐름

## 화면 구성

| 화면 | 핵심 요소 | 다음 동작 |
|---|---|---|
| 시작 | 서비스 설명, 제공 범위, 개인정보 안내·동의 | 상담 시작 |
| 상담 | 메시지, 추출 정보 확인, 질문·이유, 선택지·모름·건너뛰기 | 확인 또는 현재 정보로 결과 보기 |
| 추천 | 상태별 목록, 추천 이유, 미확인 조건, 출처·확인 시각 | 상세 또는 정보 보완 |
| 상세 | 지원 내용, 조건, 접수 기간, 근거 문단, 원문 | 신청 준비 시작 |
| 신청 준비 | 서류·절차 체크리스트, 공식 신청 링크, 사용자 기록 | 준비 상태 변경 |
| 상담 정보 | 확인된 정보·수정·삭제·만료 시각 | 재평가 또는 삭제 |

## 대표 시나리오

1. 동의 후 “경기도 안산시에 거주하는 25살 남자입니다”라고 입력한다.
2. AI는 지역·연령·성별을 제안하고 사용자가 확인하거나 제거한다. 이름이 있어도 추천 프로필에는 저장하지 않는다.
3. “25살은 만 나이인가요?”를 묻고 모르면 연령 판단을 보류한다.
4. 관련 주거 후보가 있으면 “현재 자취하며 월세를 내고 있나요?”를 묻는다. “월세 지원 후보의 주거 조건을 확인하기 위해서예요”라는 이유를 표시한다.
5. “네”를 해당 주거 필드에 반영한다. 가구원 수·소득은 필요한 후보가 있을 때 별도 질문한다.
6. 소득 질문을 건너뛰면 조건은 UNKNOWN으로 남는다.
7. 카드에 “추가 확인 필요: 가구 소득 기준”과 공고 근거를 표시한다.
8. 서류·절차를 확인하고 공식 사이트에서 직접 신청한다.
9. “제출했어요”를 기록하면 “사용자가 제출했다고 기록함”으로 표시한다. 기관 접수 확인이나 승인으로 표현하지 않는다.

위 지원 분야는 UX 예시이며 실제 모집 중인 제도를 의미하지 않는다.

## 예외 및 문구

- 결과 없음: 현재 검색 범위·필터와 정보 수정·필터 완화를 제공한다.
- 정보 부족: 현재 결과와 미확인 조건을 함께 표시한다.
- AI 실패: 입력 중복 저장 없이 재시도를 제공한다.
- 오래된 공고: 마지막 확인 시각과 원문 확인 동작을 제공한다.
- 공고 변경: 기존 체크리스트를 유지하고 변경 내용·다시 준비하기를 안내한다.
- 만료·삭제: 개인정보를 다시 표시하지 않고 새 상담을 제공한다.

“받을 수 있습니다” 대신 “입력 정보 기준으로 조건 충족 가능성이 있습니다”를 사용한다. 질문은 선택형을 우선하고 목적을 설명한다. 신청 버튼은 “공식 신청 사이트로 이동”으로 표기한다.
