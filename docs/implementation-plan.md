# 구현 계획 및 검증

v0.1 · 2026-11-25 · 문서에 정의된 목표를 단계별로 구현한다.

## 구현 순서

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 기반 | Spring MVC·Validation·JPA, PostgreSQL·Flyway, 공통 오류 | DB 마이그레이션과 기본 API 통합 테스트 통과 |
| 2. 공고 | 합성 공고 fixture, 출처·공고 버전·근거·조건 트리 | 목록·상세·버전 조회, 동일 공고 중복 방지 |
| 3. 상담 | 동의·세션 토큰·만료·삭제·프로필 | 객체 권한 검사, 필드 검증, 버전 충돌 및 삭제 검증 |
| 4. 질문 | 메시지 추출 어댑터, 사용자 확인, 질문·응답 | 나이 기준 미확인·건너뛰기·동시 응답 처리 |
| 5. 추천 | 후보 검색, 3값 조건 평가, 근거·스냅샷 | ALL/ANY, 정보 부족, 마감, 과거 버전 보존 |
| 6. 신청 준비 | 체크리스트, 사용자 상태, 공식 링크 | 공고 버전 고정, 중복 생성 방지, 항목 권한 검사 |
| 7. 실제 연동 | 공식 제공처 확인·키 발급·수집·검수 | 출처·확인 시각 표시, 수집 실패·변경 대응 |
| 8. 웹 연결 | 시작·상담·추천·상세·준비·정보 화면 | 전체 흐름 및 접근성·오류 화면 검증 |
| 9. 배포 준비 | 보존 정책·AI 처리 조건 확정, 모니터링 | 삭제 작업·속도 제한·비밀값 보호·성능 측정 |

단계 2~6은 합성 데이터와 가짜 AI 어댑터로 먼저 검증한다. 실제 제도명·금액·접수일을 임의로 만들어 운영 데이터처럼 노출하지 않는다. 각 API 구현 시 DTO로 OpenAPI 계약을 생성하고 이 명세와 차이를 검토한다.

## 필수 검증 시나리오

| ID | 상황 | 기대 결과 |
|---|---|---|
| T01 | “25살”만 입력 | 만 나이를 추정하지 않고 확인 요청 |
| T02 | 추출된 지역 미확인 | 자격 판단에는 사용하지 않음 |
| T03 | 월세 질문에 모름·건너뛰기 | false가 아닌 UNKNOWN, 같은 질문 자동 반복 없음 |
| T04 | 필수 AND 중 한 조건 FAIL | INELIGIBLE |
| T05 | 대체 OR 중 한 조건 PASS | 해당 그룹 PASS |
| T06 | 미확인 조건·규칙 미검수 | NEEDS_INFO, 확정 안내 금지 |
| T07 | 개인 세후소득과 가구 소득인정액 비교 | UNKNOWN, 추가 확인 |
| T08 | 마감·날짜 미상·예산 소진형 | CLOSED 또는 UNKNOWN, 접수 중 오표시 없음 |
| T09 | 동일 멱등 키 재시도·본문 변경 | 동일 결과 재사용 또는 409, 중복 메시지 없음 |
| T10 | 프로필 동시 변경 | 한 요청만 반영, 나머지 409 |
| T11 | 다른 세션의 질문·추천·준비 항목 | 404, 내용 노출 없음 |
| T12 | 공고·프로필 변경 후 과거 추천 조회 | 원래 결과 유지, stale=true |
| T13 | AI가 허구 문단·신청 링크 생성 | 거부하고 확인된 필드만 사용 |
| T14 | 수집 실패·같은 공고 재수집 | 기존 데이터 유지·중복 없음 |
| T15 | 삭제·만료 | 즉시 접근 불가, 관련 개인정보 정리 |
| T16 | 체크리스트 완료 | 부모 version 증가, 기관 제출·승인으로 처리하지 않음 |
| T17 | 추천 없음·출처 장애 | NO_MATCH/NO_DATA와 503 구분 |
| T18 | AI 시간 초과 후 동일 키 재시도 | 저장한 입력 재사용, 처리 재개 |

## 미결정 사항과 기본 제안

| 항목 | 현재 제안 | 결정 시점 |
|---|---|---|
| DB | PostgreSQL | 단계 1 |
| 프런트엔드 | 미정; 현재 별도 프로젝트 없음 | 단계 8 전 |
| 첫 데이터 제공처 | 개인 지원 중심 공식 출처 한 곳부터 | 단계 7 전 |
| AI 제공자·모델 | 어댑터로 분리, 합성 데이터로 비교 | 실사용 정보 처리 전 |
| 계정 | MVP 익명 24시간 세션 | 장기 보관 요구가 생기면 재설계 |
| 배포 | 미정 | 단계 9 전 |
| 실제 제출 | 공식 사이트에서 사용자가 진행 | 기관 연동·권한 확보 후 별도 설계 |

## 문서 유지 규칙

필드·상태·API를 바꾸면 API 명세, ERD, 요구사항 및 관련 테스트를 함께 검토한다. 구현 전 제안과 실제 구현 완료 상태를 README에서 구분한다. 현재 문서 작성 작업에는 코드 구현·공식 API 연결·배포가 포함되지 않는다.
